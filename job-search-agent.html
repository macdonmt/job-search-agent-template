? What this agent does

This is a self-hosted AI job search assistant that runs entirely on your own accounts — no SaaS subscription, no shared data. Once deployed, it runs on autopilot every morning.

Daily job scanning

Reads your LinkedIn email alerts, parses every job with Claude AI, and deduplicates against your history.

Smart scoring

Each job gets scored against your target companies, keywords, location preferences, and confirmed referrals.

Slack alerts

High-priority "Act Now" jobs are posted to Slack immediately, with direct links and connection counts.

Morning digest

A 7:30am summary: AI briefing, pipeline health, new roles, resume queue, and follow-up reminders.

Google Sheet tracker

All jobs land in a spreadsheet with status tracking, scoring details, and resume links.

AI resume tailoring

Two-stage pipeline: gap analysis then targeted edits, producing a tailored Google Doc per application.

💰
Cost: The only required paid service is an Anthropic API key. At typical job search volumes (50–200 jobs/day parsed), expect roughly $5–15/month in API usage. Google, Slack, and Vercel Hobby are all free for this use case.

Have all of these before starting. Setup goes much faster when everything is ready.

Accounts to create (all free unless noted)

  • GitHub account — to fork the repo. Free at github.com
  • Google account — for Gmail, Google Sheets, Google Drive. A personal Gmail account works fine.
  • Google Cloud account — to create API credentials. Free at console.cloud.google.com (requires a Google account)
  • Slack workspace — to receive alerts. Create a free personal one at slack.com — you don't need a team or company
  • Vercel account — to host the agent. Free Hobby tier at vercel.com (connect with your GitHub account)
  • Anthropic account — for the AI features. Create at console.anthropic.com and add $10–20 in API credits to start

Software to install on your computer

  • Node.js LTS — download at nodejs.org. After installing, verify with: node --version
  • Git — download at git-scm.com. After installing, verify with: git --version

LinkedIn setup

  • A LinkedIn account with job alert emails sent to your Google account's Gmail address
⚠
The Google Cloud setup (Step 2) is the most involved part of this guide. Set aside 30–45 minutes for it. All other steps are 5–15 minutes each.

1 Fork and install

1a. Fork the template repo

  1. Go to the template repo on GitHub (link in README)
  2. Click Fork in the top-right corner
  3. Name it whatever you like (e.g. job-search-agent) and click Create fork

1b. Clone your fork locally

Open a Terminal and run (replace yourusername with your GitHub username):

git clone https://github.com/yourusername/job-search-agent.git
cd job-search-agent

1c. Install dependencies

npm install

This will install all the required packages. It may take a minute. When the prompt returns, you're ready for Step 2.

1d. Create the credentials folder

The auth script expects a credentials/ folder to exist (it's gitignored — never committed):

mkdir credentials

2 Set up Google Cloud

This step authorizes the agent to read your Gmail and read/write to Google Sheets and Drive. It involves creating a Google Cloud project, enabling four APIs, creating an OAuth credential, and running an auth script.

2a. Create a Google Cloud project

  1. Go to console.cloud.google.com and sign in with your Google account
  2. Click the project dropdown at the top of the page (it may say "Select a project" or show an existing project name)
  3. Click New Project
  4. Name it something like job-search-agent and click Create
  5. Wait a moment, then make sure your new project is selected in the dropdown at the top

2b. Enable the required APIs

You need to enable four Google APIs. For each one, follow these steps:

  1. In the left sidebar, click APIs & Services → Library
  2. Search for the API name, click on it, then click Enable

Enable these four APIs:

  • Gmail API
  • Google Sheets API
  • Google Drive API
  • Google Docs API
💡
After enabling each API, use the browser back button to return to the Library page to search for the next one. You can also check APIs & Services → Enabled APIs & services to confirm all four are listed.

2c. Create an OAuth 2.0 credential

  1. In the left sidebar, click APIs & Services → Credentials
  2. Click + Create Credentials at the top, then choose OAuth client ID
  3. If prompted to configure a consent screen first, click Configure Consent Screen:
    • Choose External and click Create
    • Fill in just the required fields: App name (anything), User support email (your Gmail), Developer contact email (your Gmail)
    • Click Save and Continue through all the screens until done
    • Go back to Credentials → + Create Credentials → OAuth client ID
  4. For Application type, choose Desktop app
  5. Name it anything (e.g. job-search-agent-local) and click Create
  6. A dialog will appear — click Download JSON
  7. Rename the downloaded file to oauth-client.json and move it into your project's credentials/ folder
⚠
You also need to add yourself as a test user. Go to APIs & Services → OAuth consent screen → Test users and add your Gmail address. Without this, the authorization in the next step will fail.

2d. Run the authorization script

This script opens a browser window so you can authorize the app with your Google account. Run it from your project folder:

node scripts/auth.js
  1. A browser window will open asking you to sign in with Google
  2. Sign in with the same Google account whose Gmail you want to monitor
  3. You may see a warning that says "Google hasn't verified this app" — click Advanced then Go to [app name] (unsafe). This is expected for personal apps in test mode.
  4. Check all the permission boxes and click Continue
  5. The browser will say "The authentication flow has completed" — go back to your Terminal

The Terminal will print something like this:

✓ What you should see: Authorization complete. Token saved to credentials/token.json --- Copy this value into Vercel as GOOGLE_REFRESH_TOKEN --- 1//0gXXXXXXXXXXXXXX...

Copy the refresh token and save it somewhere safe (a text file, password manager, etc.) — you'll need it in Step 6 when setting up Vercel environment variables.

Also note your GOOGLE_CLIENT_ID and GOOGLE_CLIENT_SECRET from the credentials/oauth-client.json file you downloaded — open it and look for the "client_id" and "client_secret" fields inside "installed".

✓
After this step you have everything you need from Google Cloud: Client ID, Client Secret, and Refresh Token. Keep them safe — they're the keys to your Gmail and Sheets access.

3 Set up Slack

The agent posts job alerts and your morning digest to a Slack channel. You need a Slack workspace and a custom app with the right permissions.

3a. Create a Slack workspace (if you don't have one)

  1. Go to slack.com/get-started and click Create a Workspace
  2. Sign in with your email and follow the prompts. When asked for a company name, use anything — this is a personal workspace.
  3. Create a channel called #job-alerts (or anything you like)

3b. Create a Slack app

  1. Go to api.slack.com/apps and click Create New App
  2. Choose From scratch
  3. Name the app (e.g. Job Scout) and select your workspace, then click Create App

3c. Enable Incoming Webhooks

  1. In the left sidebar of your app settings, click Incoming Webhooks
  2. Toggle Activate Incoming Webhooks to On
  3. Click Add New Webhook to Workspace at the bottom
  4. Choose the channel you want alerts in (e.g. #job-alerts) and click Allow
  5. A webhook URL starting with https://hooks.slack.com/services/... will appear. Copy and save it — this is your SLACK_WEBHOOK_URL.

3d. Add bot scopes

  1. In the left sidebar, click OAuth & Permissions
  2. Scroll to Bot Token Scopes and click Add an OAuth Scope
  3. Add these scopes one at a time: chat:write, channels:read, files:upload, views:open

3e. Install the app and get your bot token

  1. Scroll to the top of the OAuth & Permissions page and click Install to Workspace
  2. Click Allow
  3. A Bot User OAuth Token starting with xoxb- will appear. Copy and save it — this is your SLACK_BOT_TOKEN.

3f. Get your Signing Secret

  1. In the left sidebar, click Basic Information
  2. Scroll to App Credentials
  3. Click Show next to Signing Secret. Copy and save it — this is your SLACK_SIGNING_SECRET.
✓
After this step you have three Slack values saved: SLACK_WEBHOOK_URL, SLACK_BOT_TOKEN, and SLACK_SIGNING_SECRET.

4 Initialize the Google Sheet and Gmail alerts

4a. Create your job tracker spreadsheet

Run this script from your project folder. It creates the Google Sheet, sets up all the column headers, and prints the Sheet ID you'll need later.

node scripts/init-sheet.js
✓ What you should see: Sheet created: Job Search Tracker Sheet ID: 1BxiMVs0XRA5nFMdKvBdBZjgmUUqptlbs74OgVE2upms Add GOOGLE_SHEET_ID=1BxiMVs0XRA5nFMdKvBdBZjgmUUqptlbs74OgVE2upms to your Vercel env vars.

Copy the Sheet ID (the long string after Sheet ID:) and save it — this is your GOOGLE_SHEET_ID.

💡
Open Google Sheets to confirm the spreadsheet was created. It should appear in your recent files and contain the column headers on the first row.

4b. Set up LinkedIn job alert emails

The agent reads your Gmail inbox for LinkedIn job alert emails. You need to configure LinkedIn to send those alerts to the Gmail address you authorized in Step 2.

Create job alerts on LinkedIn

  1. Go to linkedin.com/jobs
  2. Search for the types of roles you're targeting (e.g. "Director Program Management Chicago")
  3. At the top of the results, toggle on Job alert — LinkedIn will send you an email whenever new matching jobs are posted
  4. Repeat for different search variations (title variations, remote options, etc.)

Make sure alerts go to your Gmail

  1. Go to your LinkedIn Settings & Privacy → Communications → Email notifications
  2. Confirm that your primary email is the Gmail address you authorized in Step 2
  3. Under job notification preferences, make sure job alerts are enabled and set to Daily Digest or As they happen
💡
The agent looks for emails with subject lines matching LinkedIn's standard job alert format. You don't need to do anything special — just make sure the alerts are going to the right Gmail account and that you're getting them (check your inbox after setting one up).
⚠
Set up at least 3–5 different LinkedIn job alerts for different role title variations. The agent is only as good as the alerts it receives. Common variations to cover: your primary title, related titles one level up/down, and remote variants.

5 Configure your profile

These JSON files and one JavaScript file tell the agent who you are — which roles to prioritize, which companies you're targeting, and what your career history looks like for resume tailoring.

5a. Edit config/companies.json

This file boosts your score for roles at companies you specifically want to work at. Open it in any text editor and replace the examples with your actual targets:

{ "companies": [ { "name": "Stripe", "tier": 1 }, { "name": "Salesforce", "tier": 1 }, { "name": "Accenture", "tier": 2 } ], "keywords": [ "program manager", "director", "delivery manager", "agile", "technical program manager" ] }

Tier 1 companies get a higher score boost than Tier 2. Add as many or as few as you like. The keywords list controls which job titles count as a match — add all the title variations you'd consider.

5b. Edit config/referrals.json

Any confirmed referral paths you have. The agent adds +2 points to jobs at these companies and surfaces the note in Slack alerts. Start with an empty object if you have none yet:

{ "Acme Corp": { "type": "direct", "referrer": "Jane Smith", "note": "Referral — contact Jane directly for any open roles" } }

5c. Edit config/digest.json

Controls optional daily reminders in your morning digest. Disable either section by setting "enabled": false, or customize the topics:

{ "linkedin": { "enabled": true, "postDays": ["Tuesday", "Thursday"], "topics": [ "What I've learned in my job search so far", "How I approach program management at scale" ] }, "certs": { "enabled": false, "active": "PMP", "studyTopics": ["Scope management", "Risk planning"] } }

5d. Edit lib/career-facts.js

This is the AI's source of truth for resume tailoring. Every fact here should be real and verifiable — the AI uses it to enrich resume bullets without fabricating. Open the file and replace the template content with your actual career history, following the same format.

The more specific and outcome-oriented your facts are, the better your tailored resumes will be. Focus on:

  • Scale metrics (team size, budget, number of systems or products)
  • Outcomes (what shipped, what improved, what percentage)
  • Technologies and tools used
  • Cross-cutting facts that apply across multiple roles
💡
The career facts file doesn't need to be perfect on day one. You can refine it over time as you remember things or as the AI tailoring improves. Start with your two or three most recent roles and fill in older ones later.

5e. (Optional) Add your LinkedIn contacts for connection scoring

The agent can count how many LinkedIn connections you have at each company and add that to the job score. To enable this:

  1. Go to LinkedIn's data export page
  2. Request a data export and wait for the email (usually a few minutes to a few hours)
  3. Download the export ZIP and find the Connections.csv file inside
  4. Save it anywhere on your computer, then run the build script (replace the path with where you saved the file):
node scripts/build-contacts.js path/to/Connections.csv

This creates config/contacts.json with your connections. Commit it to your repo (it only contains company names and LinkedIn company IDs — no personal contact details).

6 Deploy to Vercel

6a. Import your repo into Vercel

  1. Go to vercel.com/new
  2. Click Import next to your forked repo
  3. Leave all the settings as defaults and click Deploy
  4. The first deploy will probably fail — that's expected. The environment variables aren't set yet. We'll fix that next.

6b. Generate a CRON_SECRET

This is a random string that protects your cron endpoints from unauthorized access. Generate one now:

node -e "console.log(require('crypto').randomBytes(32).toString('hex'))"

Copy the output — this is your CRON_SECRET.

6c. Add environment variables in Vercel

  1. In Vercel, open your project and go to Settings → Environment Variables
  2. Add each variable below. Set the environment to Production, Preview, and Development for all of them.
Variable Where to find it
ANTHROPIC_API_KEY console.anthropic.com → API Keys
GOOGLE_CLIENT_ID credentials/oauth-client.json → installed.client_id
GOOGLE_CLIENT_SECRET credentials/oauth-client.json → installed.client_secret
GOOGLE_REFRESH_TOKEN Printed by node scripts/auth.js in Step 2d
GOOGLE_SHEET_ID Printed by node scripts/init-sheet.js in Step 4a
SLACK_WEBHOOK_URL Slack app → Incoming Webhooks (Step 3c)
SLACK_BOT_TOKEN Slack app → OAuth & Permissions → Bot Token (Step 3e)
SLACK_SIGNING_SECRET Slack app → Basic Information → Signing Secret (Step 3f)
CRON_SECRET Generated in Step 6b above
RESUME_FULL_NAME Your full name as it should appear in tailored resume filenames (e.g. Jane Smith)
GOOGLE_DRIVE_BASE_RESUME_ID Google Doc ID of your base resume (from the Doc URL — see Step 8d)
GOOGLE_DRIVE_TAILORED_FOLDER_ID Google Drive folder ID where tailored resumes are saved (see Step 8b)

The last three variables are only needed for resume tailoring (Step 8). You can skip them initially and add them later.

6d. Redeploy

After adding all environment variables, trigger a new deployment:

  1. Go to your project's Deployments tab
  2. Click the three-dot menu on the most recent deployment and click Redeploy
  3. Wait for it to go green
✓
Once deployed, the agent is live. Crons run automatically at 7:00am (job scan) and 7:30am (digest) in your local time. See the Daily Workflow section for your ongoing routine.

7 Run your first job scan

Don't wait for tomorrow morning — trigger a manual scan now to confirm everything is wired up correctly. Replace YOUR_CRON_SECRET with the value you set in Vercel.

7a. Run the job discovery scan

curl -s "https://your-project.vercel.app/api/discover" -H "Authorization: Bearer YOUR_CRON_SECRET"
✓ Success response: {"found":12,"actNow":3}

7b. Run the morning digest

Wait one minute after discover completes, then run:

curl -s "https://your-project.vercel.app/api/digest" -H "Authorization: Bearer YOUR_CRON_SECRET"

Check your Slack channel — you should see job alerts and/or a morning digest appear. Then open your Google Sheet (find it at sheets.google.com) to see the full list of jobs that were found.

⚠
If discover returns {"found":0} on your first run, that's normal — it may mean no LinkedIn alert emails have arrived yet. Wait until you receive a LinkedIn job alert email, then run discover again.

8 Resume tailoring (advanced)

The resume tailoring feature generates a customized Google Doc for each job you want to apply to. It requires a base resume already in Google Drive and one additional environment variable.

8a. Upload your base resume to Google Drive

  1. Go to drive.google.com
  2. Create a folder called Job Search, then a subfolder called Base Resumes
  3. Upload your resume as a Google Doc (File → Upload → then open it and save as Google Doc format, or paste it into a new Google Doc)
  4. Also create a subfolder called Tailored Resumes — this is where the AI will save each generated version

8b. Get the Tailored Resumes folder ID

  1. Open the Tailored Resumes folder in Google Drive
  2. Look at the URL — it will look like: https://drive.google.com/drive/folders/1WrmUjyHY1IleflNwEkTitK9vxlqA3iAB
  3. The long string at the end is the folder ID

8c. Update the folder ID in the code

Open lib/resume.js and replace the TAILORED_FOLDER_ID value at the top with your folder ID:

const TAILORED_FOLDER_ID = 'your-folder-id-here';

Commit and push this change — Vercel will redeploy automatically.

8d. Get your base resume document ID

  1. Open your base resume Google Doc
  2. The URL looks like: https://docs.google.com/document/d/1NM7QCE79pyZAVSGk8ip.../edit
  3. The long string between /d/ and /edit is the document ID

You'll paste this document ID into Slack when using the /add command to generate a tailored resume for a specific job.

8e. Set up the Slack /add slash command

The /add command in Slack lets you paste a job URL and trigger the full tailoring pipeline. To enable it:

  1. In your Slack app settings at api.slack.com, go to Slash Commands → Create New Command
  2. Command: /add
  3. Request URL: https://your-project.vercel.app/api/slack/add
  4. Short description: Add a job and generate a tailored resume
  5. Click Save, then reinstall the app to your workspace
💡
You can skip the resume tailoring setup initially and come back to it once the daily job scanning is working well. The discovery, scoring, and digest features all work independently of resume tailoring.

★ Daily workflow

Once deployed, very little ongoing maintenance is needed. Here's what the typical day looks like.

What runs automatically (no action needed)

  • 7:00am: Job discovery scan — reads LinkedIn emails, scores and deduplicates jobs, posts Act Now alerts to Slack
  • 7:30am: Morning digest — AI briefing, pipeline counts, new roles list, resume queue, follow-ups due

What you do manually

  • Review Act Now alerts in Slack — click View Job links, use the Add Link button to generate a tailored resume
  • Update job statuses in your Google Sheet as you apply, hear back, or pass on roles
  • Add referrals to config/referrals.json as you have networking conversations
  • Tune scoring in config/companies.json as your target list evolves

Triggering a manual scan

If you want to run outside the cron schedule (e.g. after setting up a new LinkedIn alert):

curl -s "https://your-project.vercel.app/api/discover" -H "Authorization: Bearer YOUR_CRON_SECRET"

Adjusting cron timing

The cron schedule is in vercel.json. Times are in UTC. To convert: add 5 hours for CDT (summer) or 6 hours for CST (winter).

{ "crons": [ { "path": "/api/discover", "schedule": "0 12 * * *" }, { "path": "/api/digest", "schedule": "30 12 * * *" } ] }

The values above run discover at 7:00am CDT and digest at 7:30am CDT. Adjust the hour values to match your preferred time zone and wake-up time.

! Troubleshooting

Discover returns {"found":0} every day

  • Confirm LinkedIn alert emails are arriving in the Gmail inbox you authorized (not a different address)
  • Check that the emails aren't going to spam or being filtered by a Gmail rule
  • Verify the Gmail API is enabled in your Google Cloud project
  • Try revoking and re-running node scripts/auth.js to get a fresh token

Auth error / invalid_grant from Google

Your refresh token has expired or been revoked. Fix it by re-running the auth script:

  1. Go to myaccount.google.com/permissions
  2. Find your app and click Remove Access
  3. Run node scripts/auth.js again — a new refresh token will be printed
  4. Update GOOGLE_REFRESH_TOKEN in your Vercel environment variables and redeploy

Digest posts to Slack but shows no new roles

This is normal if discover ran earlier in the day and there are no jobs from the past 24 hours. The "New Roles" section only shows jobs found since yesterday's scan.

Slack 400 error on digest

The most common cause is a job section exceeding Slack's 3,000 character limit for block text — this can happen when many high-priority jobs each have long URLs. The template repo's Act Now list is capped at 5 jobs and URLs are stripped of tracking parameters to prevent this.

Resume tailoring fails or produces no output

  • Check that TAILORED_FOLDER_ID in lib/resume.js matches an actual folder you own in Google Drive
  • Make sure your OAuth account has write access to that Drive folder
  • Check Vercel's function logs for the specific error: Project → Deployments → click latest deployment → Functions tab

Crons aren't running automatically

Vercel's Hobby (free) plan does support cron jobs, but they may not run reliably under heavy platform load. If you need guaranteed daily execution, consider:

  • Setting a daily phone alarm and running the curl commands manually
  • Upgrading to Vercel Pro ($20/month) for guaranteed cron execution
  • Using a free service like cron-job.org to hit your endpoint on a schedule

I need to update my Vercel environment variables

  1. Go to your Vercel project → Settings → Environment Variables
  2. Click the variable you want to change, update the value, and save
  3. Redeploy for the change to take effect: Deployments → Redeploy
💬
If you run into something not covered here, check the Vercel function logs first — they usually show the exact error. Go to your project → Deployments → click the latest deployment → Functions tab → search for the failing endpoint.
